Change spec · csp-os-yaml/services (main) · code-anchored, no inference
Objective: If customer is in PENDING_DEACTIVATION, no ISP ticket shown to CSP. If a ticket is live and customer moves to PENDING_DEACTIVATION, remove it — with no payout to CSP.

RV holds no CL state. CAEOS guard checks only entitlement_end > window_end — no cl_state check. CAEOS InboundEventProcessingServiceImpl.java:650-705

Downstream you may have missed

TRAP RESOLVE vs CANCEL = payout. Don't dissolve via resolveObligationIfOpen — it emits SUPPLY_RECHARGE_RESOLVED, which TAS turns into candidate RESOLVED → payout. Dissolve in-place, no resolve-emit; let CL_DEACTIVATION_INITIATED own the cancel. TAS :224-253
WATCH Orphan OPEN obligation blocks future tickets. Flow 8 idempotency (:676-682) treats an open obligation as "handled" — if the connection is later rescued, no new ISP ticket is created. This is exactly why it must be dissolved.
WATCH Race condition. If APPROACHING is processed microseconds before deactivation, ticket+obligation get created, then deactivation cancels candidate (exists) and must dissolve obligation (Change #1). Both changes are needed together — neither alone closes the window.
WATCH All creation entry points. Guard must cover Flow 8 proactive + createOrEscalateReactiveObligation (supply-loss + rescue) + bulk admin (already PAUSED-guarded). Miss one → ticket re-appears.
WATCH RV gates never close. RV has no consumer for CL_DEACTIVATION_INITIATED — it keeps emitting for a deactivated connection (CAEOS now drops it, but the source keeps firing). Optional: RV consumes the event to mark the gate terminal. Same gap in CRV scheduled_expiries.
