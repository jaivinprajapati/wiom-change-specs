Warehouse Device Return (CSP / 3PL) — Acceptance & Closure

What happens when a Wiom NetBox shows up at the warehouse — returned by a CSP or by a 3PL/recovery agent. Today returns are accepted from only two custody states; on the ground devices come back from any state and Wiom learns only at the warehouse. This spec accepts every returned device, attributes who returned it, moves it to RETURNED, and runs a per-state closure (exposure, money, liability, customer). Fundamental state-machine + money change → EM and Product Head review before any architectural call.

Author (PM): Jaivin Prajapati  ·  Reviewers: Dhruv (Product Head) · EM  ·  Tier: Full

Quick Check

7-line triage.
What is changing?
Warehouse accepts device returns from CSP and 3PL from any custody state; per-state closure of money, liability, exposure & customer.
What triggered it?
Operational reality — devices change hands near CSPs and are physically returned in states the system can't accept; Wiom only learns at the warehouse; returned devices stay stuck under the CSP.
Blast radius
Custody state machine, exposure counter, carry-fee/idle, condition/damage classification, NBREC closure + ₹50 payout, DEPLOYED→connection deactivation, dispatch receipt. Consumers: Payment, Compensation, TAS, CL OS.
Reversible?
Partial — new transitions are config/flag-gated, but this is a fundamental state-machine expansion (architectural review required).
Money / PII / migration?
Money Y · PII N · Migration Y (backfill of already-stuck returned devices — engineering runbook).
OS impact / sign-off?
Asset Custody, Compensation, Payment & Settlement, Connection Lifecycle, TAS, ESR — all Pending.

A2. Why This Change WHAT

QuestionAnswer
What's wrong with current behaviour?Returns are accepted only from RETRIEVAL_PENDING and RECOVERY_HOLD. CSPs physically return devices that are still DEPLOYED, IDLE, in customer-recovery, or already LOST — and the warehouse has no way to accept them. There is no signal distinguishing a CSP return from a 3PL return, and no check on who returned it.
Who experiences it?Inventory & finance ops (devices unaccounted, exposure/liability wrong), CSPs (returns don't close, missed ₹50 recovery payout), customers (a device taken wrongfully from them is never detected).
Cost of leaving it?₹-value assets unreconciled, incorrect exposure/liability, no closure of the CSP↔device relationship, CSP trust erosion.

A6. Must-Not-Change — Regression Guard GUARD

Adjacent behaviour that must not changeWhy it's in the blast radius
Damage pricing (Compensation age-band tiers: MINOR ₹150, REPAIRABLE min(₹300,residual), NON_REPAIRABLE residual).We move the entry point but the amounts must be byte-for-byte as today.
No reversal of an already-booked LOST / DAMAGE liability when a device is returned.States 6–8 return devices that were already penalised — must not credit back.
Exposure set + exposure starts at CUSTODIED (receipt), not at dispatch.The new PCR-return handler must not shift when exposure begins.
₹50 payout gating (CSP_PICKUP / CUSTOMER_RETURN only, within 30-day SLA).New CRP-return path reuses this — must not pay outside the gate.
Existing RETRIEVAL_PENDING → RETURNED and RECOVERY_HOLD → RETURNED flows.Shared RETURNED entry; easy to disturb.
Carry-fee/idle eligibility (IDLE + was_ever_deployed) and immutability of prior ledger entries.States 2 stop accrual going forward only; the past stays.
Forward-only state machine; no retroactive state edits.New edges must be forward-effective, audited.

A7. Rules, Invariants & Edge Cases WHAT

A7.1 Rules & invariants

Rule / invariantStatement
INV — single custody stateA device is in exactly one custody state at any moment.
INV — exposure setExposure counts exactly {CUSTODIED, DEPLOYED, IDLE, CUSTOMER_RECOVERY_PENDING, RETRIEVAL_PENDING, RECOVERY_HOLD}. RETURNED is never counted.
INV — no liability reversal on returnReturning a device never reverses a booked LOST/DAMAGE liability. The only credit on return is the gated ₹50.
INV — exposure event completenessEvery exit from the exposure set emits exactly one CSP_EXPOSURE_CHANGED(−1), including DAMAGED and direct WRITTEN_OFF.
RULE — source attribution mandatoryEvery warehouse return carries returned_by_type + returned_by_id.
RULE — 3PL scopeA 3PL return is valid only for LOST + NOT_RECOVERED_FROM_CUSTOMER; any other state via 3PL is rejected.
RULE — partial receipt isolationExcluding one PENDING_CSP_RECEIPT device from an order does not block confirmation of the rest.
INV — ₹50 conditions₹50 is paid only for CSP_PICKUP/CUSTOMER_RETURN within the 30-day window.

A7.2 Edge cases

Edge / conditionIntended outcome
3PL returns a non-LOST (or CSP-custody-lost) deviceReject / exception — outside 3PL scope.
Returning CSP ≠ device's mapped CSPAccept + raise cross-CSP flag; closure proceeds.
DEPLOYED device returned; customer later says they did not hand it overFlag raised, ops follow-up; non-blocking — return still completes. [decision: confirm non-blocking is acceptable]
WRITTEN_OFF device already settled, then returnedAccept → RETURNED; no money movement.
PCR device returned while its order is still in progressRemaining devices proceed to CUSTODIED; returned one excluded; order closes partial. [conflicts with INV-ACO-DISPATCH-01 all-or-nothing — decision needed]
Device returned from LOST and QC finds damageLoss liability stands; do we additionally book damage? [decision needed — avoid double-charge]
Legacy devices already RETURNED & stuck under old CSPBackfill / re-attribution. [migration — engineering runbook]

B5. Acceptance Criteria — Verification Layer HOW

LOGIC_01 (logic · happy): CSP return from IDLE
Given a device in IDLE returned by its mapped CSP
When the Warehouse Return Event is processed
Then the device moves to RETURNED, exposure decreases by 1, carry-fee/idle stop that day
And any prior liability ledger entry is unchanged
LOGIC_02 (logic · happy): CRP return closes NBREC with ₹50
Given a device in CUSTOMER_RECOVERY_PENDING returned by the mapped CSP within the 30-day window
When the warehouse return is processed
Then the NBREC task closes as success with resolution "returned-to-warehouse"
And a ₹50 recovery payout is credited
LOGIC_03 (logic · negative): 3PL return outside scope
Given a 3PL return for a device that is DEPLOYED (or LOST with CSP_CUSTODY_LOST)
When the event is processed
Then it is rejected as an exception and no state change occurs
LOGIC_04 (logic · negative): DEPLOYED return raises flag, non-blocking
Given a device in DEPLOYED returned by the CSP
When the warehouse return is processed
Then the device moves to RETURNED, exposure −1, a wrongful-pickup flag is raised and an ops customer-confirm task is created
And the return is not blocked by the flag
COMPUTE_01 (computation · boundary): ₹50 at SLA edge
Given a CRP return with recovery_method = CSP_PICKUP
When confirmed at exactly entered_recovery + 30 days vs one second later
Then at the boundary ₹50 is paid; one second later no payout, exposure still closes
COMPUTE_02 (computation · boundary): Damage residual cap
Given a returned device classified DAMAGE_REPAIRABLE at device age 13 months
Then liability = min(₹300, age-band residual) using ≤24mo = 70% of ₹1500
And DAMAGE_NON_REPAIRABLE at the same age = full residual (uncapped)
INVARIANT_01 (A7.1): No liability reversal on return
Given a device already booked LOST/DAMAGED/WRITTEN_OFF
When it is later returned to the warehouse
Then the booked liability is never reversed or credited back
INVARIANT_02 (A7.1): Exposure-event completeness
Given any device leaving the exposure set, including via DAMAGED or direct WRITTEN_OFF
Then exactly one CSP_EXPOSURE_CHANGED(−1) is emitted
EDGE_01 (edge): Cross-CSP return
Given a device mapped to CSP-A returned by CSP-B
Then the return is accepted and a cross-CSP flag is raised
EDGE_02 (edge · transition): Partial dispatch receipt
Given a 10-device order in PENDING_CSP_RECEIPT, one device returned
When the CSP confirms receipt
Then the 9 remaining devices move to CUSTODIED and the returned one is excluded; exposure for the returned device is unchanged
REGRESSION_01 (A6): Damage pricing unchanged
Given a device classified DAMAGE_MINOR
Then the liability is exactly ₹150, identical to pre-change
REGRESSION_02 (A6): Existing handover flow intact
Given a device in RETRIEVAL_PENDING confirmed by ops
Then it moves to RETURNED with exposure −1 exactly as before
REGRESSION_03 (A6): Exposure still starts at receipt
Given an order dispatched to PENDING_CSP_RECEIPT
Then no exposure is counted until the device reaches CUSTODIED
